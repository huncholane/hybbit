Integrating Hygo Analytics with your Hugo static site involves adding the tracking script to your site's templates. The best way to do this is by creating a partial template for the script and including it in your site's footer.

<Steps>
<Step>
### Get Your Tracking Script

First, you'll need your Hygo tracking script. You can find this in your Hygo dashboard under **Site Settings > Tracking Code**. It will look something like this:

```html
<script defer src="https://app.hygo.ai/api/script.js" data-site-id="YOUR_SITE_ID"></script>
```

Replace `YOUR_SITE_ID` with your actual Site ID from your Hygo dashboard.
</Step>

<Step>
### Create a Partial Template

In your Hugo project, navigate to the `layouts/partials/` directory. If it doesn't exist, create it.

Inside `layouts/partials/`, create a new file named `hygo-analytics.html` (or a similar name).

Paste your Hygo tracking script into this new file:

```html
{{/* layouts/partials/hygo-analytics.html */}}
{{ if not hugo.IsServer }} {{/* Only include in production builds */}}
  <script defer src="https://app.hygo.ai/api/script.js" data-site-id="YOUR_SITE_ID"></script>
{{ end }}
```

**Explanation:**
- `{{ if not hugo.IsServer }}`: This Hugo condition ensures that the tracking script is only included when you build your site for production (`hugo`) and not during local development (`hugo server`). This prevents tracking your own local page views.
- Replace `https://app.hygo.ai` and `YOUR_SITE_ID` with your actual details.
</Step>

<Step>
### Include the Partial in Your Footer

Now, you need to include this partial in your site's main footer template. This is typically located in `layouts/_default/baseof.html` or a theme-specific footer partial (e.g., `layouts/partials/footer.html` or `themes/your-theme/layouts/partials/footer.html`).

Open your main base template or footer partial file. Just before the closing `</body>` tag, add the following line to include your Hygo Analytics partial:

```html
{{/* ... other footer content ... */}}

{{ partial "hygo-analytics.html" . }}

</body>
</html>
```

If you named your partial differently, make sure to use that name (e.g., `{{ partial "my-analytics-script.html" . }}`).
</Step>
</Steps>

## Configure `config.toml` (Optional but Recommended)

To make your Site ID configurable, you can use Hugo's site parameters.

<Steps>
<Step>
### Update `hygo-analytics.html`

Modify `layouts/partials/hygo-analytics.html` to use a site parameter:

```html
{{/* layouts/partials/hygo-analytics.html */}}
{{ if and (not hugo.IsServer) .Site.Params.hygoSiteID }}
  <script defer src="{{ .Site.Params.hygoInstanceURL | default "https://app.hygo.ai" }}/api/script.js" data-site-id="{{ .Site.Params.hygoSiteID }}"></script>
{{ end }}
```
</Step>

<Step>
### Add parameters to `config.toml`

Open your Hugo configuration file (e.g., `config.toml`) and add:

```toml
[params]
  hygoInstanceURL = "https://app.hygo.ai" # Your Hygo instance URL
  hygoSiteID = "YOUR_SITE_ID" # Your Hygo Site ID
```

This approach keeps your specific IDs out of the templates and makes it easier to manage for different environments if needed.
</Step>
</Steps>

## Build and Deploy

<Steps>
<Step>
### Build your Hugo site

Rebuild your Hugo site:

```bash
hugo
```
</Step>

<Step>
### Deploy

Deploy the generated `public/` directory to your web server.
</Step>

<Step>
### Verify Integration

- Open your live Hugo website in a browser.
- Navigate through a few pages.
- Check your Hygo dashboard for incoming data. It might take a few minutes for the first events to appear.
</Step>
</Steps>

That's it! Hygo Analytics is now integrated with your Hugo site and will only track visits on your production deployment.
